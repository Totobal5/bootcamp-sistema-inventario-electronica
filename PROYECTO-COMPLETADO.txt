🗄️ MODELO DE DATOS (8 ENTIDADES)
=============================================================================

1. Usuario (ADMIN, OPERADOR, CLIENTE)
2. ComponenteElectronico (inventario)
3. Placa (diseños PCB)
4. PlacaComponente (ManyToMany con cantidad)
5. SolicitudMecanizado (archivos Gerber versionados)
6. SolicitudArmado (validación de stock)
7. Tarea (workflow con estados)
8. ArchivoCertificacion (PDF/imágenes)

RELACIONES IMPLEMENTADAS:
- OneToMany bidireccional: Usuario ↔ Solicitudes
- ManyToMany compleja: Placa ↔ ComponenteElectronico (con cantidades)
- OneToMany: SolicitudArmado → Tarea
- OneToOne: SolicitudArmado → ArchivoCertificacion

🚀 FUNCIONALIDADES PRINCIPALES
=============================================================================

1. GESTIÓN DE COMPONENTES
   - CRUD completo
   - Validación de stock >= 0
   - Solo ADMIN/OPERADOR puede modificar

2. DISEÑO DE PLACAS
   - ManyToMany con componentes
   - Cantidad necesaria por componente
   - Verificación de disponibilidad

3. SOLICITUDES DE MECANIZADO
   - Upload de archivos Gerber
   - Versionado automático
   - Estados: SOLICITADO, EN_PROCESO, COMPLETADO, CANCELADO
   - CLIENTE crea, OPERADOR gestiona

4. SOLICITUDES DE ARMADO
   - Validación automática de stock
   - Descuento de inventario al confirmar
   - Relación con Placa
   - Prioridades (BAJA, MEDIA, ALTA)

5. SISTEMA DE TAREAS
   - Estados: PENDIENTE, EN_PROCESO, PAUSADA, COMPLETADA
   - Fechas automáticas (inicio, fin)
   - Solo OPERADOR puede gestionar
   - Asociadas a solicitudes de armado

6. CERTIFICACIONES
   - Upload PDF/imágenes
   - Tipos: CERTIFICACION, INSPECCION
   - OPERADOR sube, CLIENTE visualiza
